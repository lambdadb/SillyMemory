# Recent dialogue retention

## Product decision

Retain the five most recent eligible plain-text messages through the active input,
with their native roles and source order, regardless of retrieval or the previous
answer's request status. Include the entire unresolved clarification span when it
starts earlier. Normal alternating dialogue therefore retains the preceding two
user/assistant exchanges plus the current input. Blank/ineligible turns do not
consume slots, and replacement reply suffixes are never retained.

This is a usability and source-delivery contract: an ordinary follow-up should
not depend on rediscovering the immediately preceding exchange. It is not a claim
of independent benchmark superiority or proof that five messages is universally
optimal. The separate confirmation quality-improvement gate is inconclusive;
engineering adoption rests on the concrete failure/replay and delivery invariants,
with no observed new regression in the frozen controls.

Completed history storage is unchanged, including recent completed turns. The
trailing user input still waits for a reply. Generation retention and write timing
are separate: no five-message upload batching is added. Ordinarily search only the
current question; a pending request uses its complete dialogue. No Query 2,
rewriting model or additional search is added. Vector/lexical prefilters and local
selection exclude all fully retained positions before ranking and budgeting.

Managed embeddings, Bayesian English/Jev, k=100/candidateSize=100/size=50,
800-code-point boundary chunks and the 4,096-token memory budget remain unchanged.
The quarter-context memory cap remains. Recent/pending source is outside that
memory budget but within the host's total context and final delivery guard. Large
recent messages can exhaust context even with no recalled excerpts. The default
guard then stops generation with recovery guidance; it does not silently shorten
the five-message window. Disable memory to use ordinary native history.

## Evaluation protocol

The [input lock](recent-dialogue-inputs.json) records two discovery dialogues and
twelve confirmation dialogues, with the existing 24 clarification dialogues as
regression controls. Inputs/references were fixed before the first paid answer.
The same Sol/low model, pinned SillyTavern 1.19.0, 32,768 context and 4,096 output
limit apply to both conditions. Recent retention also changes the exclusion range
for fully retained source, as required to prevent duplicate memory; it is not a
comparison of query construction, storage cadence or search limits.

Histories come from the already-consumed checksum-locked LongMemEval-S dataset.
Added aliases, reminders, proposed books and follow-ups are controlled derived
conversations, not claims that these additions occurred in the original benchmark.
Identical frozen assistant prefixes are controlled schema responses through native
generation: ordinary prefixes end with `answered`, regression prefixes open
`needs_clarification`. Every final comparison reply is generated by live Sol
through the native host with real managed LambdaDB retrieval. The paid comparison
is non-streaming; streaming is covered by the local native lifecycle/delivery checks. This does not test
autonomous classification of the initial prefix or LLM-emulated user behavior.

All final answers were inspected by the agent against the frozen target and
instruction, with original responses/prompts retained. No paid judge, selective
quality retry, blinded audit or independent human review was used. Status and
literal matching are secondary signals, not factual correctness certificates.

## Completed results

| Cohort | Current-input policy | Retain 5 | Interpretation |
| --- | --- | --- | --- |
| Two discovery failures and their candidate replay | 0/2 | 2/2 | Same known-failure mechanism replay, not independent efficacy. |
| Twelve frozen ordinary follow-ups | 11/12 | 11/12 | No measured quality gain; most prefixes were already retrieved. |
| Twenty-four existing clarification controls | 23/24 reference matches | 24/24 reference matches | One interpretively ambiguous coupon case changes; no confirmed new grounded gain or regression. |

The two concrete failures asked to repeat the immediately preceding book title
in uppercase and degree subject in lowercase. With current-input-only generation,
the book text was absent and Sol asked which text; the degree response instead
repeated unrelated retrieved advice. The Retain 5 replay produced exactly
`THE SEVEN HUSBANDS OF EVELYN HUGO` and `business administration`, using the
preserved source. These results establish the local mechanism, not broad recall.

The remaining confirmation failure names a previously created Spotify playlist
as Project P, then asks its original name. Both conditions return 50 documents
without the original name, Summer Vibes, and the name never reaches selected
memory. Retain 5 preserves the alias correctly but cannot supply missing historical
evidence. This is a candidate/query issue, not current-window loss or token
packing. Query 2 is a separate future evaluation, not part of this change.

The coupon reference expects Target. Both prompts contain the coupon statement
and nearby Target discussion but no explicit sentence connecting that redemption
to Target. The candidate's added recent source is unrelated workout advice; no
new linking evidence is recovered. Sol abstains in one condition and asserts Target
in the other. Preserve the reference-score difference without claiming a grounded
quality improvement from it. The other 23 controls retain their requested facts,
absence behavior, cancellation and terminal-status semantics.

Median provider-reported input tokens in the new twelve-case cohort are
4,392.5 versus 4,940 (+547.5, about 12.5%). In the regression cohort they are
4,372.5 versus 4,808.5. These are selected native prompts, not token savings versus
full history or a pricing/general latency result. Five messages do not solve
arbitrarily distant ordinary references; the outside-window control used an
explicit IKEA-bookshelf question. No optimal-window claim is made.

## Validation and resource receipts

- `npm test`: 375 passed; runtime syntax, release metadata and pinned SDK checks
  passed. Small regressions cover the active anchor, special/blank turns, unchanged
  query text and stored-but-excluded recent source.
- `ST_SOURCE=<pinned host> ST_TEST_PORT=18136 SM_ARTIFACT_TAG=recent-retention npm run test:browser`:
  82 actual-host/Chromium checks with local LambdaDB/completion emulators.
- Same host/port/tag with `npm run test:faults`: 88 checks, including edit/delete,
  branch/disable races, uncertain writes, reload recovery and owned cleanup.
- `ST_SOURCE=<pinned host> node scripts/prompt-delivery-smoke.mjs artifacts/prompt-delivery-recent-retention-final.json`:
  17 native delivery/capacity scenarios plus source-assembly/overlap checks. Recent
  source, no-hit selection, streaming, swipe/regenerate, continuation, impersonation
  and context-loss/recovery behavior pass. Capacity tests disable continuity to
  isolate plain local completion transport; the clarification suite tests the
  structured protocol separately. All emulator runs have zero page errors/resources.
- Live evaluation: 76 final Sol calls/attempts, zero retries or rate-admission waits,
  peak concurrency one; 92 controlled prefix completions and 168 native delivery
  observations. All observations deliver only current selected memory and leave
  source history unchanged. No extra successful-call spacing is used.
- 667,734 reserved admission tokens (not billed usage), 26,888 document submissions,
  2,234 LambdaDB requests and 32 owned collection creations including gates and the
  failed regression preflight. Every collection is deleted with HTTP 404 verified.
  Saved/runtime keys are forgotten and absent from final browser/native settings;
  no credential values occur in reports. Temporary profiles/servers are removed
  and the original host extension link restored. No release/main deployment occurs.

Initial delivery attempts exposed stale assumptions about plain completion versus
the newly default structured protocol, excerpt totals and recent-context pressure.
They are retained. The first regression preflight also used inherited source hashes
from the older policy lock that do not match the raw role/content projection. The
full dataset hash was unchanged; all 24 actual source hashes were then verified
against the archived v4 producer plan before regression answers. Inputs/references
were not changed. The two candidate failure replays were declared before their
calls and are explicitly separate from the unchanged confirmation cohort.
