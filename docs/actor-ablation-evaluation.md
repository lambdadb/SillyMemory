# Actor labels and surrounding context — frozen ablation v1

This follow-up to the [actor diagnostic](actor-perspective-results.md) separates
two simultaneous changes: excerpt labels and omission of surrounding history.
It is a development prompt experiment, not a runtime change or held-out benchmark.

## Controls and schedule

Use the four pronoun cases from actor-perspective-v1, including the Korean
assistant-report control that previously passed. Preserve all 64 source messages,
questions, participant names, expected meanings and generation instructions.
Freeze **all** passages selected by the previous live run's first on repetition
for each case, including distractors. The fixture records their IDs, source text,
roles, indices, token counts and originating report byte SHA-256. Do not choose
passages using the answer oracle or perform fresh selection between conditions.

| Condition | Source history | Labels on frozen selected messages |
| --- | --- | --- |
| full-raw | All 64 messages | absent |
| full-labelled | All 64 messages | production excerpt labels |
| sparse-raw | Fixed selected old messages + recent 11 | absent |
| sparse-labelled | Fixed selected old messages + recent 11 | production excerpt labels |

The new question is message 12 of the recent window. Keep original chronological
order and native user/assistant roles. Every selected passage is one complete
source message; reject partial/multiple chunks for this protocol. Labels are
generated by the unchanged production `memoryMessages`. Full-labelled labels
only the same selected old messages, leaving every other source text untouched.
Removing labels does not free space for more passages: no backfill is allowed.
The labelled selected slice must match its prior host count and stay within 400
tokens. Full contexts use 8192 tokens, with exact retention checked in the actual
outgoing request. This intentionally avoids host truncation as a confound.

Four cases × four conditions × two repetitions = **32 answers**. Rotate condition
order by case index plus repetition index, so each of the four conditions occurs
once in every position across the four cases of each repetition. The fixture,
schedule, protocol and harness are frozen before calls. Model, temperature and
output limit remain gpt-4.1-mini-2025-04-14, 0 and 256. Do not tune wording or retry
successful answers. At most 40 attempts, with the existing bounded 5xx policy and
at least 15 seconds between actual provider starts. Preserve incomplete runs.

## Real-host path and integrity

Run the existing pinned SillyTavern 1.19.0 Generate/UI harness. A **test-only**
replacement of the extension's named interceptor transforms the ephemeral prompt
array. Disable production retrieval in all four conditions; do not claim this run
revalidates retrieval or synchronization. The previous selected set came from
live LambdaDB, and the shared harness still runs real proxy setup/cleanup gates.
The private bridge forwards the host-generated payload unchanged to the provider.

Assert the complete outgoing conversation array (text, order and roles), the
three exact system messages, reply identity, source preservation, one interceptor
invocation and the frozen labelled selection budget. Abort if the original host
history differs; independently recompute prompt evidence in the offline summary.
Source files must have identical hashes before/after execution. Preserve retry
attempts, spacing, usage, all answers and owned-data cleanup evidence.

## Interpretation and stop rule

Use the unchanged semantic actor/location rubric, with unsupported actions or
observer claims failing strict scoring. Produce randomized unscored human packets
and separate provisional assistant annotations. This experiment has no release
quality gate. Compare labels within each context size and context removal within
each label condition, paired by case and repetition. Keep all four conditions and
all negative results; do not pool them with historical off/on scores.

If errors follow labels in both context sizes, labels are implicated in these
controlled requests. If errors follow sparse history without labels, surrounding
context also matters. An interaction, inconsistent repeats or null result limits
the conclusion. Even clean separation supports only this fixture/model: it does
not prove a model-internal mechanism or generalize to quotation, multiple speakers,
adversarial text, macros, chunk boundaries or other models. Stop after the fixed
run and propose a separately validated runtime change only if justified.
