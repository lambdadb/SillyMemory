# SillyMemory 0.8.0 — experimental pre-release

Prepared release boundary: **2026-11-06**. Preparation, main promotion, version
tags and GitHub Release publication are separate steps. Confirm publication in
[GitHub Releases](https://github.com/lambdadb/SillyMemory/releases).

Supported host: SillyTavern 1.19.0 at
`06bde939fb1e9c4c8d8641d810f0a916b5bce127`, with Chromium.
Other host versions and browsers remain unverified.

## Changes from 0.7.3

- **Connect to LambdaDB** in Connection settings. Sign up or log in in a LambdaDB
  window, choose or create a project and approve the connection; SillyMemory
  receives one project key, runs the same setup test as manual setup and saves
  the key in this browser. The flow uses LambdaDB OAuth with a popup and S256
  PKCE, registers this installation once with its callback page, revokes the
  setup token afterwards and saves recovery identity only just before the key
  claim, so an approval left to expire no longer blocks later attempts. It
  requires SillyTavern on `localhost` or HTTPS. Manual endpoint/project/key
  entry remains available.
- While connected, the Connection section shows **Connected to \<project\>** with
  one **Disconnect** button instead of the connect form. Disconnect removes the
  saved key and turns memory off; saved memory is kept. With saved memory, the
  section notes that it must be deleted before using another project.
- The chat Memory panel is organized around the open chat: the on/off button
  comes first and is a filled button while memory is off, recovery actions stay
  next to the status, **Last prompt** holds the token estimates, selected memory
  and **View full memory**, and **This chat's memory** holds **Sync now** and
  **Delete this chat's memory**. Settings keep only actions for every chat.
- Plain wording throughout: "memory" instead of "remote" or "owned" memory,
  **Run setup test**, **Run connection test**, **Delete all memory**,
  **Memory added**, and not-connected messages that name Connect first.
- **Removed: frozen memory snapshots.** The Advanced snapshot section and the
  chat panel's Resume snapshot button are gone. SillyTavern's native
  **Save checkpoint**, **Create Branch** and **Back to parent chat** keep working
  as before, and SillyMemory prepares memory for whichever chat you open. There
  is no migration for chats that were saved as snapshots.
- The README is rewritten around three steps: install, Connect, turn memory on
  in a chat.

## Installation, update and activation

Install the repository URL with an empty branch field to follow public main.
Reviewers can use the preparation branch in an isolated profile before main
promotion. Update through Extensions → Manage extensions → SillyMemory → Update,
then reload. Update follows the installed Git branch, not the newest tag/Release.
Automatic updates remain disabled; no build step or server restart is needed.

**Updating from 0.7.x:** the saved key and saved memory continue to work, and
Connect is optional for an already connected browser. **Chats that were on come
up off after the update.** 0.8.0 accepts a chat's ON flag only when it was set
by this browser's current connection, so open each chat where you want memory
and choose **Turn memory on in this chat** again; synchronization reuses the
saved memory.
Frozen memory snapshots are no longer listed or resumable. Chats that were saved
as snapshots have no migration path and their behavior under 0.8.0 is not
verified; the feature had no known users. Use native checkpoints and branches
for save points.

**Updating from 0.6.0:** turn memory on in each chat where you want it. The old
global flag is not copied to every chat; chats without a saved preference start
off.

Collection/index formats, ownership tags, chunking, the Query1 search policy,
managed embeddings/reranking, recent-history alignment and token budgets are
unchanged from 0.7.3. No remote migration is introduced, and Git
installation/update checks do not prove existing-collection compatibility.

Before changing versions, preserve native chats and backups. To roll back,
disable memory and pin published `v0.7.3` using the
[release procedure](../../RELEASING.md#user-updates-and-rollback). Rollback does
not undo remote writes or deletions, and 0.7.3 cannot resume snapshots that were
never saved under it.

## Acceptance and limits

See [0.8.0 acceptance](0.8.0-validation.md) for the exact installation/update
commits, commands, retained artifacts and inherited runtime evidence. This
preparation adds no paid-provider or answer-quality experiments.

Connect was accepted on LambdaDB dev and production from SillyTavern on loopback
and on a browser-trusted HTTPS origin on 2026-11-04 and 2026-11-05; the release
acceptance below exercises it only against a synthetic issuer. Group/tool
conversations, concurrent multi-device writers and non-Chromium browsers remain
unsupported or unverified. Flattened Text Completion verification remains
unavailable. The complete-query 8 KiB limit and recent-history limits still apply.
Previewed memory, prompt verification and token estimates do not establish answer
correctness, provider receipt, cost savings or new benchmark quality results.
