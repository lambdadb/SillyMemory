# SillyMemory 0.11.0 — experimental pre-release

Prepared release boundary dated **2026-11-23**. Preparation, main promotion,
version tags and GitHub Release publication are separate steps. Confirm
publication in [GitHub Releases](https://github.com/lambdadb/SillyMemory/releases).

Supported host: SillyTavern 1.19.0 at
`06bde939fb1e9c4c8d8641d810f0a916b5bce127`, with Chromium.
Other host versions and browsers remain unverified.

## Changes from 0.10.0

- **Reranking is opt-in and off by default** (#157). Until 0.10.0 every search
  in a standard story reranked 200 candidates with LambdaDB's reranking model.
  Reranking and managed embedding share one project inference quota, and
  reranking used almost all of it, so a free project's monthly quota could run
  out within a day of active chat and then block saving as well. A standard
  story's search is now one dense vector search (k=200, 50 returned), with no
  text matching and no reranking. The new **Reranking** setting turns on the
  0.10.0 search unchanged: vector and text fusion with managed Jev reranking
  over 200 candidates. It applies from the next reply and needs no rebuild;
  collections keep their text index and analyzers. The setup and connection
  test never reranks. On English LongMemEval-S, vector-only search delivered
  complete evidence for 95.30% of annotated messages and reranked search
  98.10% ([measurements](../text-private-retrieval.md#results-summary)).
- **A used-up project quota is reported as one** (#157). LambdaDB answers HTTP
  403 when a project has used up its inference, read or write quota or reached
  its storage limit. This was shown as "Access denied. Check your project key
  and permissions." with advice to reconnect. It now names the quota, says what
  it blocks and what to do (upgrade the plan, wait for the quota to reset or,
  for storage, delete memory), and a stopped reply says how to keep chatting:
  turn memory off in that chat. The saved key and connection are kept. Other
  403 responses keep the previous message.

## Installation, update and rollback

Install the repository URL with an empty branch field to follow public main.
Reviewers can enter `release/0.11.0` or `develop` in the branch field in an
isolated profile before main promotion. Update through Extensions → Manage
extensions → SillyMemory → Update, then reload. Update follows the installed
Git branch, not the newest tag/Release. Automatic updates remain disabled; no
build step or server restart is needed.

**Updating from 0.10.0:** there is no settings or data migration and no
collection change. Search behavior changes: **Reranking** is off after the
update, because no value is saved for it, so standard stories search by vector
only. To keep the 0.10.0 search, turn **Reranking** on in settings; it uses much
more LambdaDB inference usage on every reply. Each chat's saved on/off choice,
the saved key, saved memory and Private memory stories are unaffected. The
extension manager shows version 0.11.0.

To roll back, disable memory and pin published `v0.10.0` using the
[release procedure](../../RELEASING.md#user-updates-and-rollback). 0.10.0
ignores the saved Reranking value and reranks every standard search again. Its
collections and saved memory are the same format, so no rebuild is needed in
either direction.

## Acceptance and limits

See [0.11.0 acceptance](0.11.0-validation.md) for the inherited evidence of
the merged PRs, the installation/update and browser acceptance and the checks
that were not performed.

Known limits of this release:

- The retrieval comparison behind the new default is English LongMemEval-S
  only. Vector-only search without text matching was not evaluated in other
  languages or on roleplay-specific recall such as invented proper nouns, and
  no answer-quality figure was measured for the exact default configuration.
  The README's 96.0% LongMemEval-S result was measured with reranking.
- **Text search languages** affect search only while Reranking is on; the text
  index is still built for every standard story.
- Quota errors are recognized by LambdaDB's four exact quota messages. A
  different or changed message falls back to the generic access error.
- The limits of 0.10.0 still apply: Private memory quality was validated on
  English LongMemEval-S only, group-chat answer quality was not evaluated, and
  concurrent multi-device writers and non-Chromium browsers remain unverified.
  Previewed memory, prompt verification and token estimates do not establish
  answer correctness or provider receipt.
