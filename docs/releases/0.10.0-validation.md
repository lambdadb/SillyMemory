## Maintainer manual test

On 2026-11-11 the maintainer tested develop `6b08b2a` (#151 head; #152 changes
documentation only) installed in their own SillyTavern `06bde939` with
Chromium, a live LambdaDB project and local Ollama 0.40.15 with
`qwen3-embedding:0.6b` on GPU:

- **Standard mode:** older messages were archived and recalled; deleting a
  message and the reply that referred to it removed it from the prompt.
- **Group chat:** members were added, **List order** replies worked, and a
  checkpoint opened as its own chat file.
- **Private memory:** the switch stayed locked until **Test and save**
  succeeded; a new private story was created. Its 72 LambdaDB documents were
  inspected with the CLI: the schema has no text field and no chat words appear
  in any document; metadata consists of ids, speaker names, roles, timestamps,
  revision and 1024-dimension vectors rounded to 4 decimals.
- **Endpoint outage:** with the embedding endpoint down, the reply stopped with
  the embedding message and **Retry reply**; **Test and save** failed and kept
  the saved setting; after restarting the endpoint, **Retry reply** recovered.
- **Embedding mismatch:** switching the preset to `embeddinggemma` blocked the
  story (only **Rebuild story memory** offered, reply stopped); restoring
  Qwen3 with **Test and save** recovered it.
- **Setting off:** the private story kept working with the optional rebuild
  notice; **Rebuild story memory** converted it to standard memory (72
  documents with text, verified with a consistent-read query).
- **Regex (#151):** a global **Alter Outgoing Prompt** script removing
  `<Blocks>…</Blocks>` from an archived, edited message removed the block from
  memory and from the stored LambdaDB text, and the model no longer knew the
  code; disabling the script saved the message again with the block. A
  `{{time}}` replacement script was not applied to memory, sync completed and
  the stored text kept the original word.

**Open observation (not reproduced):** once, after turning Private memory off
and chatting, the Private memory switch appeared disabled and then became
enabled on its own. The cause is unconfirmed.

## Measured candidate and results

Acceptance ran on 2026-11-11 using Node.js 24.15.0, Chromium 153 and pinned
SillyTavern `06bde939fb1e9c4c8d8641d810f0a916b5bce127` in an isolated detached
host worktree with no extension symlink for the installation run. Fresh
installation and the native Update button selected candidate
`d592f99d57039030bd870bc16022c854b9c87850` on `release/0.10.0`. The
controlled rewind started at the 0.9.1 preparation commit
`d589e908c1ced52404a2a434b1228b6c80a45555` (version 0.9.1), an ancestor of the
candidate on `develop`; the `v0.9.1` tag commit is a main merge commit and is
not contained in the branch. This checks same-branch Git updating from a 0.9.1
checkout, not a data migration from the published tag. The final acceptance
commit changes this record only; runtime, metadata, SDK and harness match the
measured candidate.

- 22 installation/update assertions passed; install and update endpoints both
  returned HTTP 200. Installed version 0.10.0, update source version 0.9.1,
  updated version 0.10.0, updated commit equal to the candidate; ownership and
  saved preferences preserved, unsaved keys absent from persistent browser
  state, no uncaught page errors or provider requests, disposable profile
  removed.
- The screenshot was opened and checked: the extension manager shows
  `SillyMemory @lambdadb 0.10.0 (release/0.10.0-d592f99)`.
- `npm test`: 282 passed; Python protocol tests: 32 passed.
- Runtime syntax (`npm run check`), development-file syntax (79 files), SDK
  bundle (0.9.0, 135,085 bytes, verified) and release metadata
  (`0.10.0 (2026-11-11)`) checks passed, including `--require-date` and
  `--base-ref origin/main` against main at `b809eaf` (0.9.1) with tags up to
  `v0.9.1` fetched.
- `npm run test:browser` on the same host with the local HTTPS LambdaDB
  emulator and synthetic OAuth issuer: 245 checks passed, zero proxy requests,
  zero remaining collections. The report records two host page errors from the
  intentional group stop scenarios (`AbortSignal was fired. Group generation
  stopped`, `Clicked stop button`); the same two appear in the #151 runs and
  are not asserted outside fault mode.
- `npm run test:private-memory:live` on the same host (runner's extension
  symlink, live LambdaDB project via `SM_ENV_FILE`, local Ollama 0.40.15 started
  for the run and stopped afterwards, deterministic loopback generator): 35

  `qwen3-embedding:0.6b` mismatch and rebuild to 1,024 dimensions. None of the
  67 audited LambdaDB request bodies carried a text field or seeded chat
  phrase; no request carried host cookies or CSRF headers. All 4 collections

  record was removed. The temporary host worktree was removed afterwards.
