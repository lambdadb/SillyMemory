# SillyMemory 0.9.1 — experimental pre-release

Prepared release boundary dated **2026-11-06**. Preparation, main promotion,
version tags and GitHub Release publication are separate steps. Confirm
publication in [GitHub Releases](https://github.com/lambdadb/SillyMemory/releases).

Supported host: SillyTavern 1.19.0 at
`06bde939fb1e9c4c8d8641d810f0a916b5bce127`, with Chromium.
Other host versions and browsers remain unverified.

## Why this release

0.9.0 introduced **Text search languages** and an analyzer notice that compares
the analyzers a story collection actually has with the current setting. A live
check against the configured LambdaDB project, run on the day 0.9.0 was
published, found that the collection-creation (HTTP 201) response carries no
index configuration. The extension read the missing list as the service
default `standard`, so a story whose collection had just been created showed
"This story's memory is indexed with: standard" with **Rebuild story memory**
until the next synchronization read the collection and cleared it. The
collection itself was created correctly with the requested analyzers; only the
report was wrong, and nothing was written or deleted remotely by the defect,
because rebuild is an explicit, confirmed action.

## Changes from 0.9.0

- **Correct analyzers for a just-created collection** (#144). On the create
  path the extension now reports the analyzers it requested, which the service
  confirmed by creating the collection; the read path still reports the
  collection's actual `indexConfigs.text.analyzers`. The unit-test fixture for
  the 201 body mirrors the real response, without index configuration.
- **Bounded live check** (#144). `npm run test:analyzers:live`
  (`scripts/analyzers-live.mjs`) creates at most two empty, owned story
  collections in the configured project (no documents, embeddings or
  searches), verifies the reported analyzers on the create and read paths, the
  notice when the setting changes and the rebuild recreation, then deletes
  both and confirms their absence. It persists the pending collection
  identities under `artifacts/analyzers-live-pending.json` before each create,
  so an interrupted run can be cleaned up by running the script again; a
  pending record for a different endpoint or project is never overwritten, and
  no new collection is created while earlier cleanup is incomplete.
  Credentials come from `.env.local` or `SM_ENV_FILE`. The Codex review of the
  script raised three P1 findings on cleanup persistence and the foreign
  record; all were fixed before merge.

## Installation, update and rollback

Install the repository URL with an empty branch field to follow public main.
Reviewers can enter the preparation branch in the branch field, or `develop`,
in an isolated profile before main promotion. Update through Extensions →
Manage extensions → SillyMemory → Update, then reload. Update follows the
installed Git branch, not the newest tag/Release. Automatic updates remain
disabled; no build step or server restart is needed.

**Updating from 0.9.0:** nothing to do after the reload. There is no settings or
data migration; existing story collections, the **Text search languages**
setting, each chat's saved on/off choice, the saved key and saved memory are
unaffected. The false notice no longer appears for a new story; a collection
that a user rebuilt on 0.9.0 after seeing it already has the configured
analyzers. The extension manager shows version 0.9.1.

**Updating from 0.8.1 or earlier:** the 0.9.0 notes apply unchanged.

To roll back, disable memory and pin published `v0.9.0` using the
[release procedure](../../RELEASING.md#user-updates-and-rollback). Rolling back
to 0.9.0 only reintroduces the false notice for newly created stories; it reads
the same documents and collections. 0.8.1 also reads memory written by 0.9.1:
documents are identical and queries name the `text` field rather than an
analyzer, so a collection created with a non-`english` analyzer set is still
searched by 0.8.1 with whatever analyzers it has.

## Acceptance and limits

See [0.9.1 acceptance](0.9.1-validation.md) for the inherited evidence of the
merged PR, the live check, the installation/update acceptance and the checks
that were not performed. This preparation adds no paid-provider or
answer-quality experiments.

Known limits of this release:

- The maintained live check is English-only by the repository's evaluation
  policy: it creates empty collections with `english` and `english`+`korean`
  and checks analyzer reporting, not search results. A one-off observation of
  Korean lexical matching made during the investigation is evidence of the
  mechanism only, not a quality claim; search quality in languages other than
  English remains unevaluated.
- The analyzer notice and the rebuild flow are verified at the module level
  against the real service by the live check, but were not exercised end to
  end through the browser UI.
- The 49-entry analyzer list has no search box; it scrolls. Each selected
  analyzer indexes the text again, which raises LambdaDB index cost.
- Group/tool conversations, concurrent multi-device writers and non-Chromium
  browsers remain unsupported or unverified. The complete-query 8 KiB limit and
  recent-history limits still apply. Previewed memory, prompt verification and
  token estimates do not establish answer correctness or provider receipt.
