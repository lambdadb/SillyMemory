# 0.11.0 installation and update acceptance

## Scope

Prepare develop `315b132` (`feat: make reranking opt-in and report used-up
project quotas (#157)`) as experimental 0.11.0, dated **2026-11-23**. The
candidate carries opt-in reranking with quota error reporting (#157), the only
change merged to `develop` after the publication of 0.10.0.
Preparation changes version metadata, the changelog title and its
Compatibility section, release notes and RELEASING only; product runtime,
dependencies and the shipped SDK bundle are those of that develop revision.

on November 9–10 for the Private memory decision, not rerun for this release.

## Measured candidate and results

Acceptance ran on 2026-11-23 using Node.js 24.15.0, Chromium 153 and pinned
SillyTavern `06bde939fb1e9c4c8d8641d810f0a916b5bce127` in an isolated host
checkout with no extension symlink for the installation run. Fresh
installation and the native Update button selected candidate
`36106eb071c8bb0a11f05df54b71a98d0e5beb58` on `release/0.11.0`. The controlled
rewind started at the 0.10.0 preparation commit
`47e900b9012a31c58a2729fa23cd550b2563d1ec` (version 0.10.0), an ancestor of the
candidate on `develop`; the `v0.10.0` tag commit is a main merge commit and is
not contained in the branch. This checks same-branch Git updating from a 0.10.0
checkout, not a data migration from the published tag. The final acceptance
commit changes this record only; runtime, metadata, SDK and harness match the
measured candidate.

- 22 installation/update assertions passed. Installed version 0.11.0, update
  source version 0.10.0, updated version 0.11.0, updated commit equal to the
  candidate; saved preferences preserved, unsaved keys absent from persistent
  browser state, no uncaught page errors or provider requests, disposable
  profile removed.
- The screenshot was opened and checked: the extension manager shows
  `SillyMemory @lambdadb 0.11.0 (release/0.11.0-36106eb)`.
- `npm test`: 289 passed; Python protocol tests: 32 passed.
- Runtime syntax (`npm run check`), development-file syntax (79 files), SDK
  bundle (0.9.0, 135,085 bytes, verified) and release metadata
  (`0.11.0 (2026-11-23)`) checks passed, including `--require-date` and
  `--base-ref origin/main` against main at `32ce846` (0.10.0) with tags up to
  `v0.10.0` fetched.
- `npm run test:browser` on the same host with the local HTTPS LambdaDB
  emulator and synthetic OAuth issuer: 247 checks passed, zero proxy requests,
  zero remaining collections. It asserts the default request (one dense `knn`
  search, no `rerank` or `candidateSize`), turning **Reranking** on for the
  next reply without a collection change, and turning it off again. The report
  records two host page errors from the intentional group stop scenarios
  (`AbortSignal was fired. Group generation stopped`, `Clicked stop button`),
  the same two recorded for 0.10.0.
- `npm run test:faults`: 136 checks passed, including an upsert answered with
  HTTP 403 `Project inference quota exceeded`: the status names the inference
  quota, keeps the key and connection and offers retry. The screenshot
  `sync-quota` was opened and checked. `npm run test:recovery`: 256 checks
  passed. Both report zero page errors, zero proxy requests and zero remaining
  collections.
- `node scripts/prompt-delivery-smoke.mjs`: 18 delivery cases passed.
- `npm run test:collections:live` on `fbf891c` (the candidate plus the first
  version of this record; runtime identical to `36106eb`) against a live
  LambdaDB project with managed embeddings, in a second detached host worktree
  of the pinned commit: 22 checks passed. It covers story and branch creation,
  an unchanged native fork with zero upserts, an earlier-point fork, rename,
  reload, deletion and the default search (`knn.queryText`, Reranking off)
  retrieving the synthetic source through the UI interceptor. 135 remote
  responses, no host proxy requests, no page errors; every collection the run
  created was deleted and the pending-cleanup record was removed. No
  generation model was called.
