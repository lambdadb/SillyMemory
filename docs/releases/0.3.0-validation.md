# 0.3.0 installation and upgrade acceptance

## Decision and bounded scope

Validate the real Git URL installation of public 0.2.0 and the host UI update to
the 0.3.0 candidate before proposing publication. Use SillyTavern 1.19.0 at
`06bde939fb1e9c4c8d8641d810f0a916b5bce127` in an isolated profile. First check
installation/settings without paid services, then use at most three synthetic
LambdaDB collections and 50 submitted documents. No generation calls, personal
chat data, provider changes or retention-expiry wait. Confirm owned cleanup before
any retry. Keep one reviewable preparation change with completed results or a
concrete blocker; keep detailed outputs and exact producers in ignored evidence.

The upgrade must preserve existing per-chat documents and settings. Explicit
story opt-in may index once, after which unchanged native forks and checkpoints
must reuse memory without upserts. Verify isolation, managed recall, key re-entry,
scoped/all-owned deletion, code rollback and return. Historical quality results
are not a new evaluation of this candidate.

Publication is not authorized by this preparation record. Main remains 0.2.0;
0.3.0 retains its `Unreleased` changelog entry until the publication boundary is
reviewed. Final results and evidence availability are recorded after the run.
