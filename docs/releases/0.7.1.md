Prepared release boundary: **2026-10-23**. Main promotion, version tags and
GitHub Release publication remain separate steps. Confirm publication in
[GitHub Releases](https://github.com/lambdadb/SillyMemory/releases).

Supported host: SillyTavern 1.19.0 at
`06bde939fb1e9c4c8d8641d810f0a916b5bce127`, with Chromium.
Other host versions and browsers remain unverified.

## Changes from 0.7.0

Frozen memory snapshots now save the same older-history partition used by
ordinary synchronization. The complete original JSONL transcript, hidden swipes
and metadata remain preserved. Recent messages stay in that transcript instead
of being uploaded solely for the snapshot. Resumed writable paths archive them
normally when later dialogue displaces them. Changed or missing older passages
still reconcile before snapshot readiness; the saved snapshot stays protected.

Documentation and development tools now focus on current behavior and final
benchmark results. Superseded experiment implementations and cohort-only tests
are retired, with [original evidence preserved](../evidence-retention.md).
The retained summary comparator's source digest resolves the maintained files.
[LongMemEval-S and BEAM profiles](../../benchmark/README.md) remain reproducible;
their recorded results are not new measurements of this patch release.

## Install and update

Install the repository URL with an empty branch field to follow public `main`.
Update through Extensions → Manage extensions → SillyMemory → Update, then reload.
Updates follow the installed Git branch. Automatic updates remain disabled;
no npm install, compilation or server restart is required.

Existing 0.7.0 per-chat activation, saved connection scope, collection/index
formats, retrieval defaults and native response/streaming behavior are unchanged.
No new storage migration or credential entry is introduced by this patch.
When updating from 0.6.0, enable memory separately in each desired chat as
explained in the [0.7.0 update notes](0.7.0.md#installation-update-and-activation).

Before changing versions, preserve native chats and backups. For rollback,
disable memory and pin published `v0.7.0` using the
[release procedure](../../RELEASING.md#user-updates-and-rollback).
Rollback does not undo remote writes/deletions or restore an older remote state.

## Acceptance and limits

See [installation/update acceptance](0.7.1-validation.md) for exact candidate
commits and measured scope. Candidate installation is not main deployment.
The checkpoint timing report separates memory preparation from chat-file
restoration, UI automation and first-answer latency; see
[the method and results](../branch-checkpoint-cost.md#memory-preparation-after-restore-ui-excluded).
This preparation adds no paid provider run or new answer-quality score.

Group/tool conversations and concurrent multi-device writers remain unsupported.
Prompt verification is distinct from answer correctness. The supported-host,
context, query-size and recent-dialogue limits remain in the [README](../../README.md).
