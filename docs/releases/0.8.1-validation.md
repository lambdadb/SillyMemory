# 0.8.1 installation and update acceptance

## Scope

Prepare develop `80594017` (`perf: upsert up to 200 documents per request
(#137)`) as experimental 0.8.1, **Unreleased**. The candidate carries the
HTTP 429 retry and fewer metadata reads (#135), the activation status, busy-wait
and Sync now removal (#136) and the 200-document upsert batch (#137) merged to
`develop` on 2026-11-06. Preparation changes version metadata, the changelog
title and compatibility section, release notes and RELEASING only; product
runtime, dependencies and the shipped SDK bundle are those of that develop
revision.

## Measured candidate and results

Acceptance ran on 2026-11-06 using Node.js 24.15.0, Chromium and pinned
SillyTavern `06bde939fb1e9c4c8d8641d810f0a916b5bce127` in an isolated host
worktree with no extension symlink. Fresh installation and the native Update
button selected candidate `482d769297eadaac3ef5b51acbef2359a5e9ffa2` on
`release/0.8.1`. The controlled rewind started at the 0.8.0 preparation commit
`052ee40e86bb86ef22404ff153409016c4f5e732`, an ancestor of the candidate on
`develop`; this checks same-branch Git updating from a 0.8.0 checkout, not a
data migration from the published tag. The final acceptance commit changes this
record only; runtime, metadata, SDK and harness match the measured candidate.

- 22 installation/update assertions passed; install and update endpoints both
  returned HTTP 200.
- Installed version 0.8.1 before and after the update, updated commit equal to
  the candidate, ownership and saved preferences preserved, unsaved keys absent
  from persistent browser state.
- No uncaught page errors or provider requests; the disposable profile was
  removed.
- The screenshot was opened and checked: the extension manager shows
  `SillyMemory @lambdadb 0.8.1 (release/0.8.1-482d769)`.
- `npm test`: 233 passed; Python protocol tests: 32 passed.
- Runtime/tool syntax (59 development files), SDK bundle (0.9.0, 135,085 bytes,
  verified) and release metadata (`0.8.1 (Unreleased)`) checks passed.
- `npm run check:release -- --base-ref origin/main` fails as expected for an
  undated candidate with `Publication requires a dated changelog entry, not
  Unreleased`; it is rerun after the entry is dated.
- `npm run test:browser` on the same pinned host with the local HTTPS LambdaDB
  emulator and synthetic OAuth issuer: 208 assertions passed; zero page errors,
  zero proxy requests, zero remaining collections. The runner's extension
  symlink was removed from the host afterwards.

## External verification and dating

- On 2026-11-06 the external tester who reported the two 0.8.0 issues installed
  `develop` at `8059401` and reported no issues for the requested checks: no
  429 at **Turn memory on in this chat** in a new chat, **Updating** rather than
  **Ready** during activation with a message sent in that window generating
  normally, failure messages naming **Retry synchronization** with **Sync now**
  gone, and a long existing chat completing its first indexing. No request log,

  `npm run check:release -- --require-date` and
  `npm run check:release -- --base-ref origin/main` were rerun; see below.
