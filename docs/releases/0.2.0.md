# SillyMemory 0.2.0 (experimental candidate)

Long-term memory for SillyTavern. **Powered by LambdaDB.**

This candidate brings the development memory and prompt-safety improvements to
one reviewable version. It is not published: the default installation still
follows the 0.1.0 `main` baseline until an approved promotion.

## Changes

- Recalled passages keep native user/assistant roles, speaker names and literal
  source text. Context retrieval handles prior user turns, assistant topics and
  explicit Continue generation.
- Identical selected excerpts share one body with all selected source positions.
  The saved budget can admit additional distinct context.
- **Memory in the last prompt** distinguishes prepared memory from memory
  verified in the final host prompt. **Stop on missing context** is enabled by
  default and cancels generation before the model request when context is lost.
  Adjust context/output settings and retry explicitly, or disable that option
  to proceed with a warning. The submitted user message remains in the chat.
- A pending final-prompt check cannot be overwritten by another generation.
  If prompt preparation fails in another extension before its final event,
  reload before trying again.

## Update and rollback

No collection migration or new credentials are required. After an approved main
promotion, use **Manage extensions → SillyMemory → Update**, reload, enter the
LambdaDB key again and re-enable memory. Ownership, recent-message settings and
the configured memory budget remain intact. Existing installations gain the
default missing-context stop behavior.

Until promotion, a candidate branch is for isolated development testing only.
If an update causes a problem, disable memory first. Advanced users can pin the
published `v0.1.0` tag for code rollback; this does not undo chat or remote-data
changes. Do not delete a memory collection simply to change code versions.

## Evidence and remaining limits

The [managed recall follow-up](../managed-packed-results.md) completed all 64
scheduled actual SillyTavern/LambdaDB/OpenAI responses and confirmed cleanup.
All 28 known-answer memory-on samples received complete required evidence.
Provisional assistant grading passed 30/32 on-mode and 4/32 off-mode answers;
two Korean quotation answers still omitted the signer. Guidance pilots did not
reliably fix that model interpretation issue and were rejected.

These are familiar, synthetic regression cases with correlated padding. They do
not establish general answer accuracy, resolve earlier reported-actor failures
in other corpora, or constitute independent human grading. The candidate remains
experimental; stable-release readiness is not claimed. The real Git URL
installation/update check passes 20 assertions, including upgrade from published
0.1.0, the new default, settings retention, key clearing and published-tag rollback.

The supported host remains SillyTavern 1.19.0. The direct-CORS candidate requires
LambdaDB access for the browser page origin, without a host proxy setting or
restart. See [direct-CORS validation](../direct-cors.md); the earlier proxy-path
results above retain their original boundary. The product uses managed embeddings and session-only keys;
no direct embedding provider integration or server plugin is required. Existing
limits on group chats, files/tools, multi-tab use and remote cleanup still apply.
