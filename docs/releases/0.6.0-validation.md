## Scope

`f9cd4778083b0c795de0b5e5e8bea113ed616b7a` as an experimental 0.6.0 candidate.

storage, generation policy, dependencies and the shipped SDK bundle are frozen
at that develop revision. Public main at acceptance served 0.5.0 at

actual pinned-host candidate installation and native Update from the main 0.5.0

provider/model requests or collection changes. Installation is not a storage

## Executed commands

Run in a clean preparation worktree with locked dependencies (`npm ci`). The host
must have no global extension symlink; the install runner creates and removes its
own disposable profile. Each artifact tag must be new.

```sh
npm test
npm run check
npm run check:sdk
npm run check:release -- --require-date
npm run check:release -- --base-ref origin/main
npm run check:release -- --tag v0.6.0
for file in scripts/*.mjs tests/*.js benchmark/*/*.mjs; do node --check "$file" || exit; done
python3 -m unittest discover -s tests -p 'test_*.py'

ST_SOURCE=/path/to/pinned/host ST_INSTALL_PORT=18179 \
SM_ARTIFACT_TAG=release060-main-baseline npm run test:install

ST_SOURCE=/path/to/pinned/host ST_INSTALL_PORT=18179 \
SM_INSTALL_BRANCH=chore/release-060 \
SM_UPDATE_FROM=c659750508cc20b90e3dcca682ab2bb169b4bedb \
SM_ARTIFACT_TAG=release060-candidate-update npm run test:install
```

The tag-name check creates no tag. The preparation branch can be removed after
merge; use its retained producer and receipts for historical reproduction. A new
branch/main installation is a new measurement. No main merge, tag or GitHub Release
is established by this preparation record. Promote develop using a merge commit,
then verify its tree and main CI; tag/Release publication remains separate.
