# SillyMemory 0.9.0 — experimental pre-release

Prepared release boundary dated **2026-11-06**. Preparation, main promotion,
version tags and GitHub Release publication are separate steps. Confirm
publication in [GitHub Releases](https://github.com/lambdadb/SillyMemory/releases).

Supported host: SillyTavern 1.19.0 at
`06bde939fb1e9c4c8d8641d810f0a916b5bce127`, with Chromium.
Other host versions and browsers remain unverified.

## Why this release

Every story collection was created with the LambdaDB `english` text analyzer,
fixed in the collection schema. Users who chat in another language still got
embedding matches, but the lexical half of the Bayesian fusion saw text that the
English analyzer tokenizes poorly, so exact names and phrases in Korean,
Japanese or other languages had no lexical match. LambdaDB offers 49 analyzers
and lets a text field index with several of them at once, but it does not
change the analyzers of an existing field, so the choice has to be made when a
collection is created and changing it later means rebuilding the collection.

## Changes from 0.8.1

- **Text search languages** (#141). A checkbox list in SillyMemory settings
  chooses the LambdaDB text analyzers for story memory created after the
  change; the default is `english`, the previous fixed value. A summary line
  names the chosen analyzers, and the last remaining language cannot be
  unchecked (the panel says "Choose at least one language." instead of silently
  falling back). The list is the pinned SDK's analyzer set, language analyzers
  first and generic ones (`standard`, `simple`, `whitespace`, `stop`, `keyword`,
  `pattern`, `fingerprint`) last; a unit test cross-checks it against the
  shipped SDK bundle. Chosen names are validated, lower-cased and de-duplicated
  before the create request; invalid stored values fall back to `english`.
- **Analyzer notice and rebuild** (#141). Preparation reads the analyzers a
  story collection actually has from the ownership read it already makes. When
  they differ from the setting, the chat panel shows "This story's memory is
  indexed with: … Rebuild to apply the current setting: …" with a **Rebuild
  story memory** button, without blocking synchronization or generation.
  Rebuild confirms, finishes earlier saves, evicts the story's cached engines,
  deletes that story's single collection after the usual ownership check,
  clears its local journals and synchronizes the open chat again so the
  collection is recreated with the current analyzers; other branches and
  checkpoints upload again when opened. The Codex review found that the cached
  engines were evicted after the deletion; the merged change evicts them first.
- **Rate-limit documentation** (#140). The LambdaDB request limit is described
  from the service source: a per-project token bucket of `rate_limit` requests
  per second (5 by default), refilled at that rate, whose 429 rejections carry
  `Retry-After` in whole seconds, which the 0.8.1 retry honours; the 1 s and 2 s
  waits apply only when the header is absent. README, the architecture note and
  the upsert batch note say where to see and raise the limit. No runtime change.

## Installation, update and rollback

Install the repository URL with an empty branch field to follow public main.
Reviewers can enter the preparation branch in the branch field, or `develop`,
in an isolated profile before main promotion. Update through Extensions →
Manage extensions → SillyMemory → Update, then reload. Update follows the
installed Git branch, not the newest tag/Release. Automatic updates remain
disabled; no build step or server restart is needed.

**Updating from 0.8.1:** nothing to do after the reload. There is no settings or
data migration; the saved key, each chat's saved on/off choice and saved memory
are unaffected. A browser state without the new setting reads as `english`,
which is what every existing story collection was created with, so no story
shows the analyzer notice until **Text search languages** is edited. Changing
the setting affects only story collections created afterwards; to apply it to
an existing story, open one of its chats and use **Rebuild story memory**,
which deletes that story's memory for every branch in LambdaDB and uploads it
again from the local chats. Embedding and reranking usage is spent again for
each re-uploaded chat. The extension manager shows version 0.9.0.

**Updating from 0.8.0 or earlier:** the 0.8.1 and 0.8.0 notes apply unchanged.

To roll back, disable memory and pin published `v0.8.1` using the
[release procedure](../../RELEASING.md#user-updates-and-rollback). 0.8.1 reads
memory written by 0.9.0: the documents are identical, and queries name the
`text` field rather than an analyzer, so a collection created with a
non-`english` analyzer set is still searched by 0.8.1 with whatever analyzers it
has. 0.8.1 does not show the analyzer notice and cannot rebuild. Rollback does
not undo a remote rebuild deletion; a story deleted by rebuild is re-uploaded
by whichever version next synchronizes its chats, and 0.8.1 creates it with
`english`.

## Acceptance and limits

See [0.9.0 acceptance](0.9.0-validation.md) for the inherited evidence of the
two merged PRs, the installation/update acceptance and the checks that were not
performed. This preparation adds no paid-provider or answer-quality experiments.

Known limits of this release:

- Search quality in languages other than English was not evaluated; choosing a
  language analyzer is expected to give lexical matches for that language, not
  measured to. No live LambdaDB run created a collection with a non-`english`
  analyzer set; the create request body and the analyzer read-back are covered
  by unit tests and the emulator only.
- The analyzer notice and the rebuild flow were not exercised end to end in a
  browser; they are covered by unit tests of their pieces and source review.
- The 49-entry analyzer list has no search box; it scrolls.
- Each selected analyzer indexes the text again, which raises LambdaDB index
  cost; LambdaDB documents that combining analyzers does not guarantee better
  relevance.
- Group/tool conversations, concurrent multi-device writers and non-Chromium
  browsers remain unsupported or unverified. The complete-query 8 KiB limit and
  recent-history limits still apply. Previewed memory, prompt verification and
  token estimates do not establish answer correctness or provider receipt.
